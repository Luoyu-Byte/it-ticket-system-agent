# Enterprise Intelligent Ticket Management System

## 企业智能工单管理与自动化平台项目规划

## 一、项目定位

项目目标：

构建一个标准化企业级 Spring Boot 工单管理系统，并在此基础上接入 AI
Agent，实现企业业务流程智能自动化。

核心理念：

> 不是做一个聊天机器人，而是让 AI Agent
> 在真实业务系统中，在权限、流程和审计约束下完成工作。

项目重点：

-   补齐 Spring Boot 企业级开发能力
-   强化数据库设计、业务建模、工程实践能力
-   将已有 Agent、Tool、Skill、RAG 经验落地到真实业务场景

# 三、第一阶段：Spring Boot 企业工单系统

目标：

-   ServiceNow

-   角色

### 工程师

-   处理工单

-   系统配置

    Permission

    Role_Permission

## 2. 工单核心系统

Ticket：

包含：

-   工单ID
-   标题
-   描述
-   类型
-   优先级
-   创建人
-   负责人
-   状态
-   创建时间

状态流转：

    OPEN

    ↓

    PROCESSING

    ↓

    WAITING_USER

    ↓

    RESOLVED

    ↓

    CLOSED

要求：

不能随意修改状态，需要符合业务规则。

------------------------------------------------------------------------

## 3. 工单历史记录

记录：

    张三

    时间：
    2026-08-10

    PROCESSING -> RESOLVED

↓

↓

↓

↓

-   标准流程问题

## 3. 复杂问题人工接管

企业不会允许 AI 完全自动。

设计：

    用户问题

    ↓

    Agent分析

    ↓

    置信度判断

    高：
    自动处理

    低：
    转人工

例如：

-   权限申请
-   安全问题
-   高风险操作

必须人工审核。

------------------------------------------------------------------------

    返回结果

# 八、项目最终简历定位

不要描述为：

"AI客服机器人"

而描述为：

> 基于 Spring Boot 构建企业智能工单管理系统，引入 AI Agent、RAG 和 Tool
> Calling，实现工单自动分类、知识检索、智能处理、人工协同以及 Agent
> 操作审计。

项目体现能力：

-   Java企业后端开发
-   数据库建模
-   权限设计
-   工作流设计
-   AI Agent工程化落地
-   企业级系统设计

------------------------------------------------------------------------

# 九、开发原则

1.  第一阶段尽量手写核心业务代码。

2.  不追求功能堆砌，优先保证业务合理。

3.  Agent不是替代系统，而是在系统约束下增强业务。

4.  重点体现：

    AI如何安全进入企业系统。
